# Prompt RSI Lab：双层提示词进化实验（语义评分 V4）

一个范围受控的 RSI 实验：第一层优化技术文章四段式中文摘要 Prompt；第二层根据开发集失败证据，优化生成候选 Prompt 的策略。网站：[实验控制台](https://rsi-evolution-lab.leoliu-dev.workers.dev)。

## 每日闭环

Cloudflare Cron 每天 01:00 UTC（北京时间 09:00）执行，GitHub Actions 于 02:00 UTC（北京时间 10:00，平台可能延迟）运行测试并归档。

1. 读取冠军、策略和历史候选；旧模型原始 KV 与历史快照保留。切换 OpenRouter 后沿用冠军提示词，但新建模型周期，清空旧评委反馈/策略试验/审计缓存，重新校准与评测，不沿用旧分数。
2. 固定评委先通过 8 个校准样例：3 个正确摘要与 5 个错误摘要（数字、否定、恢复机制、因果及 ETag 错误）。正确摘要需合规且至少 80 分，错误摘要需识别硬错误并封顶 49 分。任何校准失败就停止实验，不使用旧评分兜底。通过记录缓存 24 小时，绑定模型、数据和评委版本。
3. 从 9 篇开发文章池轮换 3 篇、独立的 6 篇验证文章池轮换 2 篇。先评测冠军，再把开发集具体错误、缺失事实及原文依据反馈给候选生成器。验证和审计文章及其评分不会进入提案输入。
4. 当前策略和挑战策略使用相同每日改进焦点、相同文章、相同摘要生成配置、每条最多 3 次提案机会。焦点按日轮换。拦截归一化重复、持久历史重复与微小改动；必要时使用预定义核验规则补位，明确标记，且不计策略胜负。
5. 策略生成、候选生成、摘要生成与语义评委全部使用 OpenRouter `nvidia/nemotron-3-ultra-550b-a55b:free`，服务地址 `https://openrouter.ai/api/v1`。关闭模型推理输出，评委使用固定提示词、温度 0 和种子（服务端不保证完全确定性），逐句核查证据。模型不直接给总分，脚本负责加权与门槛。评委与生成器是同一模型，不再是独立模型，可能产生相关性偏差，不能仅凭模型规模认定质量提高。
6. 任意矛盾、无依据断言、错误事实或反转条件都否决晋级。字数 80—450、四段标题必须合规；开发集至少提高 2 分，事实覆盖不下降；验证分、事实覆盖、准确性及条件保留不得退步。
7. 两条模型候选完成公平配对才比较策略：挑战候选开发集至少高 2 分、验证至少高 1 分，覆盖/准确性/条件不下降且无硬错误，记一胜。最多 3 个不同日期试验，2 胜晋级，否则回退。规则补位不伪装成模型胜利。
8. 3 篇独立审计文章只报告冠军效果，不参与优化、晋级或策略比较。冠军版本变化时重新测量；公开逐篇证据。
9. 保存完整输出、原文证据、语义判断、分项得分、校准结果、去重记录及实际模型调用量。单次实验逻辑调用与 HTTP 尝试均上限 64（含校准、重试、审计）。请求起始间隔至少 3.1 秒；429/5xx 最多重试一次，尊重不超过 60 秒的 Retry-After。每日额度耗尽、鉴权失败、截断输出或预算耗尽时明确失败并保留原冠军；不自动切换其他或收费模型。记录实际 token、HTTP 尝试/重试和接口报告费用；接口未报告费用不等于免费。

## 评分与证据

| 分项 | 权重 | 判断方法 |
| --- | ---: | --- |
| 事实准确性 | 40 | 被原文支持的摘要句比例 |
| 信息完整性 | 25 | 加权重要事实覆盖，部分覆盖计一半 |
| 条件与范围 | 20 | 明确保留关键条件、否定与适用范围的比例 |
| 清晰与不冗余 | 10 | 可理解、不明显跨段重复各 5 分 |
| 四段格式 | 5 | 每个规定标题 1.25 分 |

出现任何硬错误时，单篇最终分不高于 49，保留原始加权分和错误依据。字数是合规条件，不奖励越短越好。评委输出必须覆盖所有输入 ID，证据 ID 必须来自原文、摘要引文必须确实存在；结构或引文不合法有限重试后失败关闭。候选不知道评委身份之外的其他候选结果，评委输入不带候选身份。

V3 关键词 60/格式 20/精简度 20 的旧分数不可与 V4 比较。更换生成/评委模型也不能直接比较旧分数。网站曲线只绘制当前模型周期，历史表标注评分版本和旧/当前模型；每天文章轮换，因此趋势不能解读成固定测试集上的单调能力提升。

## 实验边界

文章由项目编写，覆盖超时/幂等、租约、权限、缓存、统计归因、迁移、时区等，尚待独立人工审校。验证池每三天轮换重复，不是每天新抓取文章，也不是永久隔离的最终测试集；验证结果参与选择，仍有间接过拟合风险。固定审计池也不等于长期全新盲测。语义评委可能错判，8 个校准样例不能保证全部事实错误被识别。严格质量承诺需要独立人工标注、更丰富外部语料和长期测量。

最小编辑距离只能减少同义改写，不能证明语义新颖；不承诺每天候选一定胜出。没有改进时保留冠军并公开证据，才是有效实验而非模拟上涨。

## 开发与部署

    npm ci
    npm test
    npm run check
    npm run dev

Cloudflare Builds 连接 `leoliu-png/leo_liu-RSI` 的 `main`：构建 `npm ci && npm test`，部署 `npx wrangler deploy`。发布成功以构建检查与线上健康接口模型为准。Cloudflare Worker `rsi-evolution-lab` 使用 KV、Cron、静态网页与服务端 OpenRouter HTTP 接口；不再调用 Workers AI。

`OPENROUTER_API_KEY` 仅放在 Cloudflare Secret（`npx wrangler secret put OPENROUTER_API_KEY`），不得提交源码或网页。本地开发通过未跟踪的 `.dev.vars` 或受控进程环境注入，禁止写入可归档数据。`src/model.js` 和 `wrangler.jsonc` 中的模型与服务地址必须保持一致。免费端点的额度和可用性由 OpenRouter 决定；不自动付费，不绕过限流。实验仅发送项目人工编写的文章，勿用于机密或个人数据。

`RUN_TOKEN` Secret 保护 `POST /api/admin/run`；同一天 V4 已完成则跳过。旧 `/api/admin/rescore` 返回 409，语义评分必须真正重新运行，不能只改旧分数标签。每日数据变化通过 KV 实时展示，不需要重新部署 HTML。

新模型使用 `rsi:v4:openrouter-nemotron3-ultra:state`、`rsi:v4:openrouter-nemotron3-ultra:run:YYYY-MM-DD`；旧 V2/V3/V4 原始键不删。同一天旧模型完成也不阻止新模型实验。每日归档为 `snapshots/YYYY-MM-DD-v4-openrouter-nemotron3-ultra.json`，不覆盖同日旧档；归档校验必须有语义证据与通过的校准记录。代码测试使用明确标记的模拟评委；真实调用另行验证并存档，不能将模拟测试称为真实质量提升。

## 主要文件

- `src/corpus.js`：18 篇文章、事实/条件证据、每日轮换与校准样例。
- `src/evaluator.js`：固定语义评委、校验、确定性评分、校准和调用预算。
- `src/model.js`、`src/openrouter.js`：统一模型配置、服务端鉴权、限流/重试、费用计数与脱敏。
- `src/evolution.js`：公平策略配对、候选去重、晋级回退、反馈隔离与状态迁移。
- `src/index.js`：公开 API、鉴权与 Cron。
- `public/index.html`：有图、有表、有分项和逐篇证据的实时控制台。
- `test/`：评分边界、证据真实性、校准失败、去重、公平性、迁移与归档测试。
- `scripts/snapshot*.mjs`：GitHub 每日归档及证据完整性校验。
- `src/benchmark.js`、`src/holdout.js`：保留的 V3 复现实验材料，不用于 V4 主循环。
