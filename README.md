# Prompt RSI Lab：双层提示词进化实验（语义评分 V4）

一个范围受控的 RSI 实验：第一层优化技术文章四段式中文摘要 Prompt；第二层根据开发集失败证据，优化生成候选 Prompt 的策略。网站：[实验控制台](https://rsi-evolution-lab.leoliu-dev.workers.dev)。

## 每日闭环

Cloudflare Cron 每天 01:00 UTC（北京时间 09:00）将当天任务交给持久化执行器；04:00 / 12:00 UTC（北京时间 12:00 / 20:00）是看门狗，只恢复缺失的调度，不重置重试或费用计数。GitHub Actions 在北京时间 10:00 / 16:00 / 23:55 检查并归档，平台可能延迟。

1. 读取冠军、策略和历史候选；旧模型原始 KV 与历史快照保留。切换模型后沿用冠军提示词，但新建模型周期，清空旧评委反馈/策略试验/审计缓存，重新校准与评测，不沿用旧分数。
2. 固定评委先通过 8 个校准样例：3 个正确摘要与 5 个错误摘要（数字、否定、恢复机制、因果及 ETag 错误）。正确摘要需合规且至少 80 分，错误摘要需识别硬错误并封顶 49 分。任何校准失败就停止实验，不使用旧评分兜底。通过记录缓存 24 小时，绑定模型、数据和评委版本。
3. 从 9 篇开发文章池轮换 3 篇、独立的 6 篇验证文章池轮换 2 篇。先评测冠军，再把开发集具体错误、缺失事实及原文依据反馈给候选生成器。验证和审计文章及其评分不会进入提案输入。
4. 当前策略和挑战策略使用相同每日改进焦点、相同文章、相同摘要生成配置、每条最多 3 次提案机会。焦点按日轮换。拦截归一化重复、持久历史重复与微小改动；必要时使用预定义核验规则补位，明确标记，且不计策略胜负。
5. 策略生成、候选生成、摘要生成与语义评委全部使用 FeedMob LiteLLM `minimax-m3`，服务地址 `https://litellm.feedmob.it.com`。接口仅发送标准聊天参数，不发送 OpenRouter 专用 reasoning 字段；评委使用固定提示词与温度 0，逐句核查证据。当前配置不发送 seed 参数，记录 evaluationSeed 为 null；不能保证重复调用完全确定。模型不直接给总分，脚本负责加权与门槛。评委与生成器是同一模型，可能产生相关性偏差，不能仅凭模型规模认定质量提高。
6. 任意矛盾、无依据断言、错误事实或反转条件都否决晋级。字数 80—450、四段标题必须合规；开发集至少提高 2 分，事实覆盖不下降；验证分、事实覆盖、准确性及条件保留不得退步。
7. 两条模型候选完成公平配对才比较策略：挑战候选开发集至少高 2 分、验证至少高 1 分，覆盖/准确性/条件不下降且无硬错误，记一胜。最多 3 个不同日期试验，2 胜晋级，否则回退。规则补位不伪装成模型胜利。
8. 主实验的开发集、验证集与策略比较证据先提交。3 篇独立审计文章只报告冠军效果，不参与优化、晋级或策略比较；审计失败单独标为 pending/failed，自动补测或给出警告，不撤销已完成的主实验。未完成审计不冒充已通过。
9. 每篇摘要、评分及模型原始响应都逐步保存为检查点，成功步骤不会在续跑时重做；已产生的合法候选即时进入持久去重，开发集反馈在中断后仍保留，不泄露验证/审计内容给提案模型。当天逻辑调用和 HTTP 尝试分别最多 64，跨重试累计而非每次清零。请求起始间隔至少 3.1 秒；单请求 90 秒超时，临时网络故障/429/5xx 最多一次请求级重试，尊重 Retry-After。独立诊断探针不属于每日实验。

## 每日可靠运行与故障处理

- 单一 `EvolutionRunner` Durable Object 按模型周期串行协调每日任务，SQLite 是权威存储，KV 为兼容镜像；不会使用最终一致的 KV 假装原子锁。状态与当日结果在同一 SQLite 事务提交。原 KV 历史记录保持不变。
- 每次推理前保存已用预算；恢复时不清零。摘要、有效评分、校准、候选及生成响应均可复用；结构错误的原始响应保留。策略 JSON 有一次修复机会，候选结构错误计入每候选最多 3 次机会；不通过编造证据或放宽评分让实验变绿。
- 每个执行片最多约 10 分钟，在剩余时间不足以安全完成请求与重试时暂停，30 秒后续跑；持久 Alarm 在推理前写入，进程退出后仍能恢复。重放同一天的提交不重复晋级、不重复记录策略胜负。
- 临时故障最多 5 次失败，间隔 5 / 15 / 60 / 180 分钟；每日报警执行片最多 16 次，23:50 CST 截止。鉴权、额度耗尽、预算耗尽、校准拒绝及无法修复的证据结构直接停止，不无限消耗接口。外部服务整日不可用时不能保证测评完成，必须如实标出阻塞。
- 网站公开阶段、已保存步骤、累计调用、失败原因和下一次续跑时间；主实验与审计状态分开。GitHub 将成功测量与 `-status.json` 故障/运行中证据分别归档；故障不是成功实验，最终停止仍以 error 告警。
- 09:00 首次启动；12:00 / 20:00 看门狗补缺失 Alarm。配置依据：[Cloudflare Alarms](https://developers.cloudflare.com/durable-objects/api/alarms/) 与 [执行时限](https://developers.cloudflare.com/durable-objects/platform/limits/)。不承诺外部服务永远在线，也不承诺每天候选一定胜出。

## 评分与证据

| 分项 | 权重 | 判断方法 |
| --- | ---: | --- |
| 事实准确性 | 40 | 被原文支持的摘要句比例 |
| 信息完整性 | 25 | 加权重要事实覆盖，部分覆盖计一半 |
| 条件与范围 | 20 | 明确保留关键条件、否定与适用范围的比例 |
| 清晰与不冗余 | 10 | 可理解、不明显跨段重复各 5 分 |
| 四段格式 | 5 | 每个规定标题 1.25 分 |

出现任何硬错误时，单篇最终分不高于 49，保留原始加权分和错误依据。字数是合规条件，不奖励越短越好。评委输出必须覆盖所有输入 ID，证据 ID 必须来自原文、摘要引文必须确实存在；结构或引文不合法有限重试后失败关闭。候选不知道评委身份之外的其他候选结果，评委输入不带候选身份。

V3 关键词 60/格式 20/精简度 20 的旧分数不可与 V4 比较。更换生成/评委模型也不能直接比较旧分数。网站曲线只绘制当前模型周期，历史表标注评分版本和旧/当前模型；每天文章轮换，因此趋势不能解读成固定测试集上的单调能力提升。

## 实验边界

文章由项目编写，覆盖超时/幂等、租约、权限、缓存、统计归因、迁移、时区等，尚待独立人工审校。验证池每三天轮换重复，不是每天新抓取文章，也不是永久隔离的最终测试集；验证结果参与选择，仍有间接过拟合风险。固定审计池也不等于长期全新盲测。语义评委可能错判，8 个校准样例不能保证全部事实错误被识别。严格质量承诺需要独立人工标注、更丰富外部语料和长期测量。

最小编辑距离只能减少同义改写，不能证明语义新颖；不承诺每天候选一定胜出。没有改进时保留冠军并公开证据，才是有效实验而非模拟上涨。

## 开发与部署

    npm ci
    npm test
    npm run check
    npm run dev

Cloudflare Builds 连接 `leoliu-png/leo_liu-RSI` 的 `main`：构建 `npm ci && npm test`，部署 `npx wrangler deploy`。发布成功以构建检查与线上健康接口模型为准。Cloudflare Worker `rsi-evolution-lab` 使用 KV、Cron、静态网页与服务端 LiteLLM HTTP 接口；不再调用 Workers AI。

`MODEL_API_KEY` 仅放在 Cloudflare Secret（`npx wrangler secret put MODEL_API_KEY`），不得提交源码或网页。本地开发通过未跟踪的 `.dev.vars` 或受控进程环境注入，禁止写入可归档数据。`src/model.js` 和 `wrangler.jsonc` 中的模型与服务地址必须保持一致。服务额度、费用与可用性由所配置的 LiteLLM 服务决定；不自动切换其他模型，不绕过限流。实验仅发送项目人工编写的文章，勿用于机密或个人数据。

`RUN_TOKEN` 或独立 `MAINTENANCE_TOKEN` Secret 保护 `POST /api/admin/run`（202：排入持久任务，不在 HTTP 请求中同步跑长实验）与 `POST /api/admin/probe`（一次模型连接诊断）。不改变已有 RUN_TOKEN。重复排队不会重置预算或重跑完成任务；旧 `/api/admin/rescore` 返回 409。网站从 Durable Object 读取权威状态，不需要重新部署 HTML。

新模型使用 `rsi:v4:litellm-minimax-m3:state`、`rsi:v4:litellm-minimax-m3:run:YYYY-MM-DD`；优先从 Laguna 状态迁移冠军与历史候选，清空旧评分、失败反馈、挑战策略试验和审计缓存，旧 V2/V3/V4/Nemotron/Laguna 原始键不删。同一天旧模型完成也不阻止新模型实验。每日归档为 `snapshots/YYYY-MM-DD-v4-litellm-minimax-m3.json`，不覆盖同日旧档；归档校验必须有语义证据与通过的校准记录。代码测试使用明确标记的模拟评委；真实调用另行验证并存档，不能将模拟测试称为真实质量提升。

## 主要文件

- `src/corpus.js`：18 篇文章、事实/条件证据、每日轮换与校准样例。
- `src/evaluator.js`：固定语义评委、校验、确定性评分、校准和调用预算。
- `src/model.js`、`src/openrouter.js`：统一模型配置、服务端鉴权、限流/重试、费用计数与脱敏。
- `src/evolution.js`：公平策略配对、候选去重、晋级回退、反馈隔离与状态迁移。
- `src/journal.js`、`src/runner.js`：逐步检查点、SQLite 原子提交、串行任务、持久 Alarm、限次重试与每日截止。
- `src/index.js`：公开 API、鉴权与 Cron。
- `public/index.html`：有图、有表、有分项和逐篇证据的实时控制台。
- `test/`：评分边界、证据真实性、校准失败、去重、公平性、迁移与归档测试。
- `scripts/snapshot*.mjs`：GitHub 每日归档及证据完整性校验。
- `src/benchmark.js`、`src/holdout.js`：保留的 V3 复现实验材料，不用于 V4 主循环。
